## Cómo retomar sin repetir la auditoría

Leer AGENTS.md y CLAUDE.md, este documento, la sección9 del plan y últimas entradas E07. Ejecutar git status/log y comprobar versión/rama/remoto antes de editar. No resetear ni pisar cambios ajenos. Activar únicamente el siguiente subpaso concreto; implementar → pruebas significativas → revisión por agente independiente → corregir → commit convencional → actualizar progreso. No expandir el alcance por refactors cosméticos.

Los tests de este programa se ejecutan en copia hermética, nunca directamente en el checkout personal: hubo fixtures históricos con efectos sobre rutas reales. En esta máquina, `/tmp/coco-evolution-location` apunta al entorno Node22/mirror, `/tmp/coco-check-increment.py` sincroniza cambios y ejecuta checks bajo sandbox (sin credenciales reales ni red externa; loopback permitido). No sobrescribir HOME. Scripts temporales pueden desaparecer: si faltan, recrear copia limpia aislada siguiendo E01 antes de probar. Logs conservados bajo `.dev/evolution/e01-baseline/logs` (ignorados por Git) y en Actions para la release.

Comandos de aceptación: `pnpm check:release` (incluye cobertura, REPL y build); `npm pack --ignore-scripts`; instalar tarball en consumidor temporal y `node scripts/smoke-package.mjs <consumer> <version>`. Para publicar usar workflow Release/tag correcto, que selecciona next para prereleases y compara integridad remota. No cambiar dist-tags estables ni marcar deploy correcto solo por haber empujado un tag.
